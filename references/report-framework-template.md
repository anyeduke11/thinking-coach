# 汇报框架模板

## 一、标准汇报结构

```markdown
一、数据概览（30秒）
├─ 关键数据：同比/环比变化
├─ 趋势变化：时间节点、拐点
└─ 范围说明：全局还是局部

二、原因分析（2分钟）
├─ 外部因素（简述，约20%）
│   ├─ 市场环境
│   ├─ 竞品动态
│   └─ 政策变化
├─ 内部因素（重点，约60%）
│   ├─ 直接原因
│   ├─ 深层原因
│   └─ 根本原因
└─ 原因归类
    ├─ 能改进的
    └─ 难改变的

三、改进方案（2分钟）
├─ 短期措施（本周/本月）
│   └─ 具体动作
├─ 中期措施（下季度）
│   └─ 具体动作
└─ 需要的支持
    └─ 资源/决策/协调

四、预期与承诺（30秒）
├─ 改善预期（务实）
├─ 关键里程碑
└─ 后续汇报节奏
```

---

## 二、汇报黄金比例

| 部分 | 占比 | 说明 |
|-----|------|------|
| 陈述事实 | 30% | 数据、趋势、范围 |
| 分析原因 | 40% | 根因分析、原因归类 |
| 改进方案 | 30% | 措施、时间、支持 |

## 四、关键话术模板

### 开场话术

**标准开场**：
> "领导，我来汇报一下[主题]。[数据确实不太理想/情况有些变化]，但我已经做了分析，也找到了原因和改进方向，想请您把把关。"

**主动担责开场**：
> "领导，[项目/指标]这次没有达到预期，主要责任在我。我已经复盘了原因，也想好了改进方案，向您汇报一下。"

### 讲原因话术

**外部因素**：
> "外部环境有一定影响，[具体情况]。"

**内部因素**：
> "但核心问题在我们内部。[直接原因]，深层原因是[深层原因]，根本上是[根本原因]。"

**专项复盘**：
> "[专项]这次确实没有产出，复盘下来发现[原因]，这个我们已经列入改进计划。"

### 讲方案话术

**提出方案**：
> "针对这些问题，我建议：第一，[方案1]；第二，[方案2]。这两项我准备[时间]就启动。"

**请求支持**：
> "另外，[支持事项]需要请您帮忙协调一下，具体是[具体内容]。"

### 结尾话术

**标准结尾**：
> "后续我每[X]周向您汇报进展。如果中间遇到卡点，我再及时请示您。"

**承诺结尾**：
> "这次的问题我会负责到底，[时间节点]前给您一个明确的结果。"

## 五、不同场景的汇报变体

### 场景1：业绩下滑汇报

```markdown
一、数据概览
- 销售同比下滑X%，从X月开始
- 整体下滑，非局部问题

二、原因分析
- 外部：市场环境、竞品动态（简述）
- 内部：人员变动、机制缺失（重点）
- 根因：[机制问题]

三、改进方案
- 短期：[动作]
- 中期：[动作]
- 需要支持：[资源/协调]

四、预期与承诺
- X周内[措施]落地
- 每两周汇报进展
```

### 场景2：项目延期汇报

```markdown
一、项目状态
- 当前进度：X%
- 延期时间：X天/周
- 影响范围：[范围]

二、延期原因
- 直接原因：[原因]
- 根本原因：[原因]
- 责任归属：[说明]

三、补救方案
- 追赶措施：[措施]
- 资源需求：[需求]
- 新的时间节点：[时间]

四、风险预案
- 可能的再次延期风险：[风险]
- 应对措施：[措施]
```

### 场景3：问题复盘汇报

```markdown

- 问题是什么：[描述]
- 影响程度：[程度]

- [展示5个为什么链条]
- 根本原因：[根因]

三、改进措施
- 短期：[措施]
- 长期：[机制改进]
- 防复发：[措施]

四、经验总结
- 教训：[教训]
- 可复用经验：[经验]
```

## 七、汇报原则

### 要做的

| 原则 | 说明 |
|-----|------|
| 先讲结果 | 开门见山，不绕弯子 |
| 主动担责 | 内部问题主动认领 |
| 有方案 | 不只报问题，要有对策 |
| 数据支撑 | 用数据说话 |
| 务实承诺 | 不过度承诺 |

### 不要做的

| 原则 | 说明 |
|-----|------|
| 不甩锅 | 不推卸责任 |
| 不隐瞒 | 不隐瞒关键信息 |
| 不空谈 | 方案要具体可执行 |
| 不找借口 | 外部因素简述即可 |
| 不过度承诺 | 预期要务实 |
