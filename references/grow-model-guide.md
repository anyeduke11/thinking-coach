# GROW模型完整指南

## 一、模型概述

GROW模型是一种教练式对话框架，由四个阶段组成：

| 阶段 | 英文 | 中文 | 核心问题 |
|-----|------|------|---------|
| **G** | Goal | 目标 | 你想达成什么？ |
| **R** | Reality | 现状 | 现在的真实情况是什么？ |
| **O** | Options | 选项 | 你有哪些选择？ |
| **W** | Will | 行动 | 你决定怎么做？ |

---

## 二、各阶段详解

### G阶段：Goal 目标

**核心目的**：帮助用户明确想要达成的结果

**三个关键问题**：

| 问题 | 目的 | 示例 |
|-----|------|------|
| 首要目标是什么？ | 明确核心诉求 | "争取领导理解和支持" |
| 理想结果是什么？ | 具体化成功画面 | "领导主动提出帮忙协调资源" |
| 底线是什么？ | 管理预期，降低焦虑 | "最差被要求复盘，但不是直接否定" |

**引导技巧**：
- 如果用户目标模糊，追问"具体来说，你希望发生什么？"
- 如果用户目标太多，追问"如果只能达成一个，哪个最重要？"
- 如果用户没有底线，追问"什么结果是你绝对不能接受的？"

**输出模板**：
```
## 目标确认

| 维度 | 内容 |
|-----|------|
| 核心目标 | [提炼后的目标] |
| 理想结果 | [具体描述] |
| 底线接受 | [可接受的最差结果] |
```

---

### R阶段：Reality 现状

**核心目的**：帮助用户全面了解真实情况，找到问题根因

**两个子阶段**：

#### R-1：事实梳理

使用5W1H框架收集事实：

| 维度 | 问题 | 说明 |
|-----|------|------|
| What | 发生了什么？ | 具体事件/数据 |
| When | 什么时候？ | 时间节点/趋势 |
| Where | 在哪里？ | 范围/区域/渠道 |
| Who | 涉及谁？ | 相关人员/部门 |
| Why | 为什么？（初步） | 可能的原因方向 |
| How | 怎么样？ | 已采取的措施/效果 |

**引导技巧**：
- 让用户先摆事实，不急于解释原因
- 不确定的信息标注"待确认"
- 区分"客观数据"和"主观判断"

#### R-2：根因分析

使用"5个为什么"深挖：

```
问题：[表面问题]
  ↓
第1个为什么：直接原因是什么？
  ↓
第2个为什么：为什么会有这个原因？
  ↓
第3个为什么：继续追问...
  ↓
第4个为什么：继续追问...
  ↓
第5个为什么：根本原因是什么？
```

**原因归类**：

| 类型 | 示例 | 能否改进 |
|-----|------|---------|
| 外部因素 | 市场环境、竞品动作、政策变化 | ❌ 难以改变 |
| 内部因素 | 人员、流程、机制、产品 | ✅ 可以改进 |

**输出模板**：
```
## 现状分析

### 事实清单
| 维度 | 内容 |
|-----|------|
| What | ... |
| When | ... |
| Where | ... |
| Who | ... |

### 根因链条
[展示5个为什么的分析过程]

### 原因归类
| 类型 | 具体原因 | 能否改进 |
|-----|---------|---------|
| 外部 | ... | ❌ |
| 内部 | ... | ✅ |
```

### O阶段：Options 选项

**核心目的**：帮助用户设计策略选项，预判效果

**两个子阶段**：

#### O-1：策略选项

列出2-3种策略选择：

| 策略 | 做法 | 优点 | 风险 |
|-----|------|-----|------|
| 策略A | ... | ... | ... |
| 策略B | ... | ... | ... |
| 策略C | ... | ... | ... |

**常见策略类型**：

| 策略类型 | 适用场景 | 特点 |
|---------|---------|------|
| 全盘托出型 | 需要展现诚意 | 诚实但可能被动 |
| 聚焦机制型 | 需要展现建设性 | 不甩锅，有方案 |
| 先外后内型 | 外部因素明显 | 渐进呈现，给缓冲 |

#### O-2：改进方案

针对根因列出改进方案：

| 时间维度 | 方案 |
|---------|------|
| 短期（本周） | 立即可做的动作 |
| 中期（本月） | 需要协调的动作 |
| 长期 | 机制层面的改进 |

#### O-3：二阶思维预判

预判策略的连锁反应：

```
策略：[选择的策略]
  ↓
一阶效应：直接结果是什么？
  ↓
二阶效应：这个结果会带来什么？
  ↓
三阶效应：继续追问...
  ↓
需要准备的问题：[领导可能追问的点]
```

**输出模板**：
```
## 选项分析

### 策略选择
| 策略 | 做法 | 优点 | 风险 |
|-----|------|-----|------|
| ... | ... | ... | ... |

**用户选择**：策略X

### 改进方案
| 时间 | 方案 |
|-----|------|
| 短期 | ... |
| 中期 | ... |

### 预判问题
| 领导可能问 | 准备的回答 |
|-----------|-----------|
| ... | ... |
```

### W阶段：Will 行动

**核心目的**：形成可执行的计划和话术

**四个输出**：

#### W-1：汇报框架

```markdown
一、数据概览（30秒）
├─ 关键数据
├─ 趋势变化
└─ 范围说明

二、原因分析（2分钟）
├─ 外部因素（简述）
├─ 内部因素（重点）
└─ 根因结论

三、改进方案（2分钟）
├─ 短期措施
├─ 中期措施
└─ 需要的支持

四、预期与承诺（30秒）
├─ 时间节点
└─ 后续汇报节奏
```

#### W-2：关键话术

| 场景 | 话术 |
|-----|------|
| 开场 | "领导，我来汇报一下...数据确实不理想，但我已经做了分析..." |
| 讲原因 | "外部有一定影响，但核心问题在内部..." |
| 讲方案 | "针对这两个问题，我建议..." |
| 结尾 | "后续我每两周向您汇报进展..." |

#### W-3：改进计划表

| 措施 | 具体动作 | 时间节点 | 责任人 | 需要支持 |
|-----|---------|---------|-------|---------|
| ... | ... | ... | ... | ... |

#### W-4：检查清单

| 检查项 | 是否准备好？ |
|-------|-----------|
| 数据准确 | ☐ |
| 根因清晰 | ☐ |
| 方案具体 | ☐ |
| 话术熟练 | ☐ |

## 三、对话原则

### 教练式原则

| 原则 | 说明 | 违反的表现 |
|-----|------|-----------|
| 不跳跃 | 每阶段确认后再进入下一阶段 | 用户还没回答就推进 |
| 不代答 | 通过提问引导用户思考 | 直接给出答案 |
| 不评判 | 接纳用户回答，帮助提炼 | 否定或纠正用户 |
| 要确认 | 关键节点复述确认 | 假设理解正确 |
| 要等待 | 给用户思考时间 | 急于推进 |

### 提问技巧

| 技巧 | 说明 | 示例 |
|-----|------|------|
| 开放提问 | 不预设答案 | "你觉得原因是什么？" |
| 聚焦提问 | 缩小思考范围 | "最关键的因素是什么？" |
| 追问深化 | 引导深入思考 | "能具体说说吗？" |
| 选择辅助 | 提供选项帮助决策 | "是A还是B？或者有其他考虑？" |

---

## 四、时间分配建议

| 阶段 | 时间占比 | 说明 |
|-----|---------|------|
| 问题识别 | 10% | 判断类型，选择模型 |
| G阶段 | 15% | 明确目标 |
| R阶段 | 40% | 事实梳理+根因分析（最关键） |
| O阶段 | 20% | 策略选择+预判 |
| W阶段 | 15% | 形成计划+话术 |

---

## 五、常见问题处理

| 问题 | 处理方式 |
|-----|---------|
| 用户回答模糊 | 追问"具体来说..."、"能举个例子吗？" |
| 用户回答偏离 | 温和引导"这一步我们聚焦的是X，让我换个问法..." |
| 用户想跳过 | 提醒跳过的风险，但尊重用户选择 |
| 用户情绪化 | 先接纳情绪，再引导回到事实 |
| 用户想换模型 | 确认当前阶段是否完成，再切换 |
